# P1 · 节点注册与双节点任务协议 v1 草案

状态：待实现。P1 验收使用两个独立 Mock Connector。PostgreSQL 持久化任务及事件，单实例 Dispatcher 从 Outbox 派发，Connector 用 WebSocket，Web 用 SSE。现有轮询 PoC 继续作为迁移基线，既有 Mock 节点需重新注册，旧任务可保留供历史查看。

## 1. 身份与授权

| 动作 | 允许的身份与范围 |
|---|---|
| 签发接入码、撤销节点、设置默认 Agent | 当前工作空间 Owner 或 Admin |
| 兑换接入码 | 持有未使用且未过期的接入码。工作空间由码记录决定 |
| 上线、续租、回报结果 | 节点凭据仅代表该 Node。任务回报要求目标 Node、当前连接代次、Attempt 与租约均匹配 |
| 发起任务 | 当前空间的 Owner、Admin 或 Member，且目标 Agent 已获授权。Viewer 不发起任务 |
| 节点 A 委派给 B | A 持有正在执行的父任务的有效租约，发起用户仍可执行任务，目标位于同一空间，且 A 的配置允许委派给 B |
| 读取或取消任务 | Owner/Admin 可管理当前空间任务，Member 可管理自己发起的根任务及其子任务。Viewer 仅可读获授权的任务 |
| 读取引用或产物 | 对具体资源重新鉴权。能查看任务状态的身份不自动拥有底层资源读取权 |

所有请求通过数据库身份解析空间。跨空间或无权发现的资源返回 404，已知资源上的未授权操作返回 403，无效凭据返回 401。拒绝事件记录请求标识、动作和原因，凭据及任务正文不进入审计。撤销成员后立即禁止后续读取、委派与资源访问，并对其尚未进入终态的任务发出取消请求。撤销节点则关闭连接并使当前租约失效，由服务端终结受影响 Attempt，状态记为执行失联或结果未知，禁止继续回报。

## 2. 注册与连接

1. 管理端调用 `POST /api/v1/workspaces/:workspaceId/enrollments`，指定节点名称、宿主类型及用途。默认 10 分钟有效，数据库只保存接入码摘要。
2. Connector 调用 `POST /api/v1/connector/enroll`。服务端在同一事务消费接入码并创建稳定 Node ID，返回一次节点凭据。并发兑换只成功一次。兑换响应丢失时，由管理员撤销对应节点并重新签发。
3. Connector 带节点凭据建立 `/api/v1/connector/ws`。首条 `node.hello` 提供协议版本、宿主版本及能力清单。服务端核对预配能力并返回 `node.welcome`，分配连接代次及心跳参数。
4. 每 10 秒发送心跳，连续约 30 秒无心跳标为离线。重连复用 Node ID，新连接替代旧连接，迟到的断开事件仅能更新自己的连接代次。
5. WebSocket 消息包含 `v`、`type`、`messageId`、`payload`，响应携带原请求标识。消息大小上限初值 64 KiB。版本不支持、字段错误和限流均返回明确错误。部署时使用 HTTPS/WSS，凭据不放 URL。

## 3. 双节点任务

| 方向 | 消息或接口 | 规则 |
|---|---|---|
| Web → Server | `POST /api/v1/workspaces/:workspaceId/tasks` | 提交目标 Agent、输入和幂等键。原子写入 Task、初始事件和 Outbox |
| Server → A 或 B | `task.assign` | 提供 taskId、attemptId、lease、leaseExpiresAt、必要输入及授权资源引用 |
| Connector → Server | `task.ack` | 明确接收。相同 Attempt 不重复启动执行。已过期或撤销的租约拒绝 |
| A → Server | `task.delegate` | 携带父任务 Attempt 与租约、目标 B、摘要、引用、幂等键。P1 限一层子任务，禁止自委派和回环 |
| Connector → Server | `task.event`、`task.complete`、`task.fail` | 绑定 Attempt、租约及节点事件序号。ACK 后才接收进度和终态。重复消息返回已有处理结果 |
| Server → Connector | `task.cancel` | 幂等转交取消请求。Connector 确认停止后回报 `task.cancelled` |
| Web ← Server | `GET /api/v1/workspaces/:workspaceId/tasks/:taskId/stream` | SSE 使用服务端持久事件序号作为 ID，按 `Last-Event-ID` 或 `afterSeq` 补读 |

任务状态为 `queued → assigned → running → succeeded/failed`。取消待执行任务可直接进入 `cancelled`。运行中先进入 `cancel_requested`，收到停止确认再进入 `cancelled`。完成回报先提交且有效时保留完成结果。超时无法确认停止则标记结果未知。父任务取消时把取消请求传播给尚在运行的子任务。

发起请求按空间、发起身份、幂等键去重。同键同内容返回原任务，同键不同内容报冲突。提交前由事务检查状态，再分配事件序号并写入事件。节点事件用 `attemptId + nodeEventSeq` 去重，服务端事件用 `taskId + seq` 排序。完成事件与任务状态在同一事务提交。Outbox 至少投递一次，持久 Task 为事实来源。

## 4. 断线、重放和取消

- Connector 以带随机抖动的指数退避重连。握手附带未完成 Attempt 及最后确认序号。服务端确认仍有效的 Attempt 后，重绑定到新连接代次，再接收缓存中的未确认事件。已失效的 Attempt 停止提交。旧连接的消息拒绝。
- ACK 超时先重发同一分配。租约默认 30 秒，可通过心跳登记活跃 Attempt 续租。失效后禁止旧 Attempt 写入。已知可安全重放的 Mock 文本任务可获得新 Attempt。结果未知或具有副作用的任务进入失败或人工确认流程。
- Web 重连按最后成功处理的 SSE 序号继续。事件序号同时用于前端去重。会话或成员权限撤销后，关闭活动流，并在复连时拒绝请求。
- 用户取消可重试请求，服务端重复处理同一取消意图。取消前的进度仍可查。终态写入后仅接受幂等回执，不再修改结果。

## 5. 可复现验收

| 编号 | 操作 | 预期 |
|---|---|---|
| N01 注册 | 创建主、隔离两个空间。在主空间签发 A/B 两个码，对其中一个码并发兑换 | 各节点只有一条身份记录，重复兑换失败，隔离空间看不到 A/B |
| N02 在线 | 启动 A/B，再停止 B 的心跳并恢复 | 管理台显示 B 离线，重连恢复在线，Node ID 不变 |
| T01 委派 | Web 发任务给 A，A 委派给 B；B 回传进度和结果，A 回传最终结果 | UI 能查看父子任务及目标，两者各有唯一终态 |
| T02 恢复 | B 中途断线，Web 同时断开；在租约有效期内重连 B，再恢复 Web | 有效 Attempt 继续，未确认事件补报，Web 补读无缺号或重复展示 |
| T03 重放 | 重放 assign、ACK、同一事件和终态；让旧租约过期后尝试写入 | 同一 Attempt 不重复启动，持久事件只记一次，旧租约写入被拒 |
| T04 权限 | 以 Viewer、隔离空间用户及非目标节点分别尝试提交、读取或回报 | 服务端按范围拒绝，数据库无越权写入 |
| T05 取消 | 依次验证排队取消、运行中确认停止、取消与完成并发 | 各任务只有一个可解释的终态，父任务取消传播至子任务 |
| T06 撤销 | B 执行中撤销 B；另一次执行中撤销发起成员 | B 无法重连或回报，相关 Attempt 终结；成员后续访问失败，进行中任务触发取消 |
| T07 持久化 | 重启服务后重新打开任务详情 | 父子关系、已有事件和终态仍可读取 |

验收记录保留服务端日志、父子任务 ID、事件序号、各 Attempt 和浏览器步骤。测试环境使用专用工作空间与独立节点配置。
