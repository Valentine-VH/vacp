# P0 · DSH 与 OpenCode 宿主验证清单

状态：待验证。本规格定义实测步骤和通过条件。具体插件 API、命令与兼容版本由实际宿主验证确定。

## 环境与证据

准备独立测试 profile、空的临时工作目录、专用测试工作空间和脱敏输入。对每个宿主记录精确版本、安装来源、插件产物摘要、Node/OS、profile、启动模式、复现命令和结果。凭据经本地安全配置注入，证据仅保留节点、会话、任务和工具调用标识。测试接收器只返回固定文本，受控执行用无副作用的文本任务。

| 宿主 | 愿景 PoC 中的职责 | 首轮验证重点 |
|---|---|---|
| DSH Desktop | 真实委派发起端 | Cordis bundle 加载、工具注册、实际会话中的委派调用、卸载后资源释放 |
| DSH CLI | 同一发布包的命令行兼容性 | 选定能承载 Agent 会话的 profile，验证依赖服务、同一工具与退出清理 |
| OpenCode | 真实委派接收端 | 选定 Plugin + 受控会话入口，验证独立会话启动、输出采集、状态回报和取消 |

Desktop 和 CLI 使用同一构建产物验证，各自使用独立节点身份。若某个 profile 缺少依赖服务，记录缺失服务和替代 profile，保持各宿主结论分开。OpenCode 插件加载、会话控制和事件订阅可以分别验证，最后用同一任务关联证据。

## 验证步骤

| 编号 | 操作 | 通过证据 |
|---|---|---|
| H01 安装 | 根据目标版本的上游文档或源码确认入口，加载最小验证插件，再卸载并重启 | 加载时出现唯一注册项，卸载后工具、监听器及连接释放。记录配置和实际调用入口 |
| H02 工具 | 在 DSH Desktop 和 CLI 各开真实会话，让 Agent 调用 `vacp_delegate_task`，发送目标标识、固定文本和幂等键到受控接收器 | 捕获真实工具调用和任务 ID，重复提交得到同一 ID。区分宿主工具注册成功和实际模型调用成功 |
| H03 接收 | 在 OpenCode 加载验证插件或受控桥接，送入一条携带关联 ID 的文本任务，分别启动两个任务 | 能获得两个不同的会话 ID，内容互不串用。记录启动入口、结果来源，以及哪些输出可以关联到指定任务 |
| H04 事件 | 让接收端产生至少一条中间事件和一条终态；如果宿主只提供整段结果，明确标注批量输出能力 | 对照宿主日志和适配输出，记录会话 ID、事件顺序、最终状态和输出片段 |
| H05 取消 | 启动可等待的任务，提出取消，再观察宿主终态。另测完成和取消几乎同时发生 | 分别记录取消请求已受理、宿主确认停止、完成先发生，以及宿主无确认时的结果。进程强停只可在独占测试进程验证，并单列其语义 |
| H06 恢复 | 运行期间断开连接再重连；重启宿主再验证可否恢复原执行 | 记录会话与任务关联、结果是否能补报、不可恢复时如何判定中断。工具重复注册或任务重复启动判为失败 |
| H07 权限 | 用无效或已撤销凭据连接，再测试跨空间目标及未授权工具请求 | 请求被拒绝，未创建目标宿主会话，记录可对应请求 ID 的错误 |

H01–H06 可先对受控测试接收器验证宿主能力。H07 和正式重连、撤销使用 P1 的服务端接口补验。DSH 接收任务属于可选能力，另行记录验证；OpenCode 接收能力是主演示的前置条件。

## 判定

每项填入「通过」「部分通过」「阻塞」和证据路径。通过的能力才加入上报清单。仅支持批量输出时仍可验证执行和终态，流式能力单列。无法确认宿主停止时只记录取消尝试，不能标记取消成功。若真实 OpenCode 接收入口不可用，记录受控桥接可行性和限制。Mock 执行只计入 P1。
