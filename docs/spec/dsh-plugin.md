# VACP DSH 插件设计

在 `plugins/dsh` 维护一个 Cordis bundle，Desktop 和 CLI 使用同一个发布包。以实际安装的 DSH 版本和 profile 建立兼容矩阵，分别记录可加载的入口、宿主提供的服务和测试结果。插件兼容范围由宿主约束，与 VACP Server 的 Node 26 基线独立。

| 入口 | 职责 | 首版 |
|---|---|---|
| 共用 Runtime 插件 | 节点身份、连接与心跳、任务委派与事件读取、注册 Agent 工具 | 必需 |
| Desktop UI | 连接状态、配置、任务入口 | 按需增加，由宿主 UI 扩展点加载 |
| CLI 命令 | 连接诊断与任务查询 | 按需增加，复用共用 Runtime |

发布包通过 `package.json` 的 `dsh.bundle` 声明补丁，由 profile 加载。宿主共享依赖通过 peer dependencies 声明。每个入口只注入自己需要的服务。打包和安装遵循 [DSH 官方插件文档](https://deepseek-harness.github.io/deepseek-harness/en/develop/basic/publish)。

## 连接和身份

### 用户登录和资源发现

安装后在 DSH 插件填写服务地址，通过 VACP 账号登录。插件读取可用工作空间及其模型目录，将每个有启用模型的空间注册为一个 Provider。在普通会话选择「VACP · 工作空间名」下的模型时，宿主按需换取空间会话令牌，直接调用 VACP 的 OpenAI 兼容网关。插件将登录令牌存入宿主的凭据存储，退出时撤销账号会话并撤下已注册的 Provider。账号密码只用于登录请求。

试验版 `@vacp/plugin-dsh@0.4.1` 可在 DSH Desktop `0.2.3-alpha.2` 登录、使用工作空间模型，并浏览「Skill 仓库」「MCP 仓库」和「插件仓库」。目录共用工作空间选择。Skill 展示版本和安装状态，MCP 展示启用服务的认证方式。插件仓库按版本下载并校验 SHA-256。安装包可以从 VACP 侧栏的「插件市场」下载，再从 DSH「插件 → 添加插件」安装并启用。工作台左侧「VACP」和「设置 → VACP 账号」都能打开账号页。首版为文本模型使用 32,768 Token 的上下文和 4,096 Token 的输出能力默认值，Skill 与 MCP 的宿主注册留待后续实现。

### 任务节点

插件依赖运行时无关的 Connector SDK。配置包含服务地址、工作空间关联的节点身份及凭据引用。首次注册使用一次性凭据，后续重连使用同一个节点身份。节点凭据存放在受保护的本地凭据存储，日志仅记录节点及任务标识。工作空间归属由服务端按节点身份判定。

每个运行实例维护一条连接。断线后退避重连，卸载或退出时清理 socket、监听器与定时器。Desktop 和 CLI 若同时运行，首版分别注册实例，避免共享节点身份导致连接互踢。

## 任务和会话

首版在两个宿主注册同一个 Agent 工具 `vacp_delegate_task`，输入包含目标 Agent、任务说明及可选产物引用。Server 校验目标和相关资源的工作空间权限，接收后返回任务 ID。调用方按任务 ID 查询进度和结果。断线或请求超时时，同一次提交复用原幂等键。

DSH 管理本地会话及上下文。VACP 记录节点和会话引用，委派时传递必要摘要与获授权的产物引用。任务接收、取消及状态上报的适配依赖已验证的 DSH 运行时接口。验证通过前，使用 Mock Connector 验证接收端，DSH 只上报已验证能力。

## 验收

- 使用同一份打包产物安装到 DSH Desktop 和目标 CLI profile，登记各自的 DSH 版本与 profile 名。
- 两端均能连接 VACP，并由 Agent 调用工具将任务委派给 Mock Connector，随后读取结果。
- 验证重连复用节点身份、重复提交不重复建任务、撤销凭据后无法重连。
- 验证跨工作空间委派被拒绝，卸载后连接与定时器释放。
- 单独记录真实 DSH 接收任务与取消行为的验证状态。
